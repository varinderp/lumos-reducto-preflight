# Lumos

Lumos estimates the cost of a Reducto document-processing job before it runs.
It includes a browser simulator and a `POST /api/estimate` endpoint that use the
same pricing engine.

[Hosted demo](https://varindersaini.com/projects/lumos)

## What it does

- Uses document metadata—not file contents—to estimate a job: names and page
  counts for ordinary documents, and names plus expected non-empty-cell counts
  for spreadsheets.
- Builds a Lumos profile manually or from imported Reducto configuration JSON.
- Returns low, likely, and high USD estimates with an
  `allow`, `review`, or `deny` policy decision.
- Does not run Reducto or incur a Reducto fee when creating an estimate.
- Keeps Legacy Parse as the default and offers opt-in r‑1 Beta pricing for
  standalone Parse.
- Prices OCR data return, prompted blocks/custom regions, and Advanced Chart as
  separate Parse, Extract, or Split add-ons.
- Estimates spreadsheet Parse or Extract usage from user-entered non-empty-cell
  counts without inspecting or uploading workbook contents.

## Run locally

Requires Node.js `>=22.13.0`. The included `.nvmrc` pins `22.13.0`.

```bash
nvm use
npm ci
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

No environment variables or Reducto credentials are required for the simulator
or estimate API.

```bash
npm test
npm run lint
```

## Estimate API

Build or import a configuration in the simulator, select **Apply
configuration**, then select **Copy Lumos profile**. Store that JSON in your
application and send it as `pipeline` for each estimate.

```http
POST /api/estimate
Content-Type: application/json
```

```js
const pipeline = await loadSavedLumosProfile();

const response = await fetch("/api/estimate", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    documents: [{ name: "contract.pdf", pages: 18 }],
    pipeline,
    policy: { max_total_usd: 10 },
  }),
});

if (!response.ok) throw new Error("Estimate failed");
const result = await response.json();
```

- `documents` is required metadata. Send `name` and `pages` for an ordinary
  document. For XLS, XLSX, XLSM, XLTX, XLTM, CSV, or QPW, send `name` and
  `estimated_non_empty_cells`; omitting the cell count keeps the known subtotal
  but makes the estimate incomplete. Do not send file contents.
- `pipeline` is the required Lumos profile generated by the simulator, whether
  the configuration was created manually or imported from Reducto.
- `policy.max_total_usd` is optional and defaults to `10`.
- `processing_context` is optional. Use `extract_input: "jobid"` or
  `split_input: "jobid"` only when that endpoint reuses an already billed Parse
  result.

The response includes the estimate range, cost breakdown, priced usage,
completeness status, excluded cost factors, and policy decision. Production
applications should call this endpoint through an authenticated server.

## Important boundaries

- Spreadsheet files are never priced as pages. Lumos prorates Reducto's
  documented cell-credit ratios and uses `$0.01 / credit` as a clearly labeled
  Lumos default; consult your Reducto rate card for the applicable price.
- Spreadsheet Split, Classify, Edit, OCR, prompted-processing, and chart costs
  remain excluded. Lumos returns the known subtotal as incomplete instead of
  guessing those contributions.
- The optional `/api/reducto` verification route sends real files, an API key,
  and a pipeline ID to Reducto only after explicit confirmation. It may incur
  Reducto charges. Spreadsheet files are rejected before upload. Protect the
  route with authentication and rate limiting.
